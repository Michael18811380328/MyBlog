主要内容：
﻿
1、介绍产品
什么是产品？ 有一定特点，可以解决问题的一个通用的东西
产品有哪些分类？ B端，C端，G端，不同分类不同的特点；实体产品，虚拟产品，移动端等等；不同行业医疗教育等。
产品经理主要职责？研究产品怎么做的人（通常是软件，也有智能化硬件）
产品经理应该会哪些技能？ 分析需求，将用户的需求挖掘出来，转换成文字和图片形式
﻿
2、如何发现问题？
如何思考？
什么是目标用户？给我们创造价值的用户是核心目标用户，核心用户有具体的特征（年龄，性别，学历，场景，行业）
如何抓住目标用户？针对不同用户，选择不同的营销手段（捆绑式，优惠券形式，高端服务，线上服务，股东型）
场景化分析是什么？5W分析，在特定场景中，挖掘用户的需求，提高用户对产品的预期
如何收集需求？望闻问切，观望用户的操作，倾听用户的声音，询问用户细节（问卷、访谈）切身实地感受用户
需求如何分类？根据重要性和紧急性，安排四个象限进行区分
用户故事是什么？把需求转换成一个故事，最终按照这个故事进行验收产品
﻿
3、如何解决问题？
需求分析方法：马斯洛体系5层，人性的弱点7种
评价优先级的方法：Kano 模型评级优先级（调查问卷-分析属性-Kano投图分析）有些功能必不可少（用户登录，手机验证码），有些功能是亮点非必须（例如npm输入密码捂眼睛的可爱交互）有的需求不要用（摇一摇的广告），进行投图，根据曲线选择是否做，重要性和紧急型分析
如何评估功能价值：某个功能的性价比 = 功能带来的收益/制作功能付出的资金成本，这个在用户定制功能很重要。
用户体验：用户从使用前的感官，使用中交互操作，使用后的心情等维度，感受一个产品的体验。
用户体验的目标：有用，易用，友好，容错，吸引力，品牌
﻿
4、如何以书面形式展示？-项目立项
项目方案的内容：产品名称、背景调研、公司情况，项目提出考虑的问题（基本方案）：是什么项目、为什么要做、项目的作用（带来收益）是否是公司主要业务？核心流程是什么？
可行性分析：市场需求，资源供应，功能规模，开发技术，设备选型，环境影响，资金筹措，盈利能力。产品团队主要考虑：市场需求、环境影响（目标市场现有规模，市场未来发展情况、用户描述、竞品分析）、盈利能力。​
产品规划的主要维度：产出 MRD 产品规划书，包括产品定位，目标用户，核心功能，产品结构，版本规划
立项说明书：包括上面的产品概况，可行性分析，产品规划三部分。
评审流程：产品团队开发团队开会，决定细节，产出 立项申请表（产品主管，开发主管签字）​
﻿
5、如何以图片逻辑形式展示？思维导图（逻辑绘图）
思维导图的作用：把复杂想法和结构，以简洁清楚的图形方式展示出来
软件: 本地的 xmind 在线的 processon
使用类型：发散思维，聚合思维，形象描述，压缩内容，结构化思维，逻辑思维
实际应用：单位汇报，个人总结，产品规划，产品架构
Xmind 具体操作：整体逻辑架构，节点-联系-属性，主题链接分享，重在使用
﻿
6、如何以动态效果形式展示？墨刀（原型设计）
墨刀操作：左侧是图层，中间是画布，右侧编辑某个组件的属性
静态原型设计：选择机型-划分页面功能区域-逐步完成（实现静态 HTML），也可以使用 AI，Sketch，Figma 等软件实现
动态交互设计：类似PPT中动作，或者JS中事件触发机制，某个行为会触发页面切换效果。包括页面整体切换，组件内部动态效果切换。
长页面和固定组件的实现：长页面需要设置滚动效果，页头页脚浮动悬浮按钮设置固定定位
项目的演示和导出：导出为不同客户端需要的效果（默认是图片或者动图）

1.2 认识产品经理章节介绍

第一章 认识产品经理

分成下面的小节

1.3 合格的产品经理

什么是产品：有主要的功能，解决一定问题的东西。可以是有形的电动机，也可以是无形的软件。

什么是产品经理：把产品的主要功能想清楚，让用户用起来方便，而不是用户骂这个产品不好用（早期12306抢票软件）。

产品经理需要解决谁（产品的受众），在什么情况下（使用场景），遇到什么事情（具体需求）。

优秀的产品经理：满足功能，用户体验良好，做出来的产品有价值。

1.4 产品经理的分类

产品经理有哪些类型，有哪些特点？

根据产品分类：

  • 网页产品经理

  • 移动产品经理

  • 电商产品经理

  • 数据产品经理——对应不同相关经验

不同公司/不同产品，对应的行业，客户，内容，级别都不一样。

相对于程序员的通用性，产品经理更专一化，不同行业产品差距很大。

根据产品对象和行业

toC 淘宝，抖音，小红书（电商，短视频，内容，旅游）

toB CRM系统，SaaS 系统，OA 系统

toG 政府网站，公安系统

智能硬件产品

根据工作侧重点不用

  1. 功能：关注产品功能，解决用户需求，设计页面效果

  2. 策略：根据用户和软件的生命周期，用户画像，设计推荐策略

  3. 商业运营：参与商业化运营，营收场景设计，广告变现，对收入利润和 ROI 负责

  4. 数据分析：大数据平台和数据挖掘，研究数据价值，数据埋点，数据驱动决策

  5. 用户体验：关注用户心理，UI UX 和视觉效果

级别

  1. 产品助理：独立完成圆形设计，需要别人带

  2. 产品经理：独立完成某一个部分的需求收集+需求分析

  3. 高级产品经理：负责某一个产品线或者业务线，带团队

  4. 产品总监：整体公司的产品规划

1.5 产品经理的岗位职责

1、产品开发流程

分析问题-可行性研究（技术可行性，经济可行性）-需求报告

软件设计-概要设计，详细设计

编码实现-集成测试

运行维护

2、对应的团队和人员

产品部：产品经理（产品的生命周期，产品是否要做，产品具体怎么做，对应 MDR PDR 等文档） UI、UX

技术部：前端，后端，运维，测试

项目部：项目经理（项目的人员和排期）

如果团队规模较小，可能产品经理还需要兼职其他岗位的职能（测试运维，项目经理）

3、产品开发的误区

画原型的：产品经理不仅仅画原型图，还需要进行可行性分析，需求分析

管项目的：产品经理不是项目经理，主要负责产品的生命周期

需求混淆：对于客户运营老板自己的需求，哪些需要做，哪些不需要做，要区分清楚

职能混淆：产品经理和其他部门是平级的，并不是上下级领导关系。

1.6 产品经理能力素质

专业技术，指的是基本技能（MRD，PRD），这部分是产品经理必须懂得的，具体对应下面的技能和软件（红色是必须的）

MRD: 需求收集，可行性研究

PRD:需求分析，原型图设计

综合素质，指的是和团队成员综合的软实力，有效推动产品落地。

1.12 认识产品经理章节总结

总结第一章内容

产品：解决某个问题的东西

2.1 问题思考维度章节介绍

本章从多个维度分析，问题如何思考？

  • 从用户的维度——抓住核心用户（重点）为什么，是什么，怎么做（对应三个小节）

  • 场景化分析——不同场景下的用户行为

  • 需求收集和辨别

  • 用户故事（可视化）

2.2 为什么要抓住核心用户

了解用户的付费点，更好的优化产品。

用户分类：

  • 目标用户（已经使用我们的产品）

  • 潜在用户（目前没有使用我们的产品）

  • 种子用户（内测用户）愿意尝鲜，愿意给我们产品提出意见，积极反馈

  • 核心用户（创造主要的利润来源）

保持市场竞争力：给核心用户提供更好的体验，增量时代已经过去，存量时代为主，同质化严重，供给大于需求

产品推广更聚焦：资源有限情况下，优先解决核心用户的核心需求

一个产品无法满足所有用户的需求，我们设计和宣传时需要做出一定的取舍。

核心用户创造的价值最大，所以我们需要抓住核心用户的核心需求。​

2.3 核心用户的特征

核心用户有哪些特征？

  • 供需关系：服务端和消费端（打车软件，司机还是客户）

  • 人口统计学：年龄，性别，地区，学历，消费能力（例如母婴用品，对年龄和性别敏感）

  • 熟悉程度：一次性用户（婚礼纪），老用户（美团口碑淘宝），专家用户（雪球）

  • 业务场景：教育行业

  • 用户身份：黄金，白金，钻石用户

  • 公司规模：中小公司SaaS，大公司，上市公司，垄断公司

产品需要根据运营的数据，对产品核心用户进行分析

案例：分析中公教育的核心用户

供需关系：学生+教师

人口统计学：20岁，1-2线城市，本科以上（性别不限）

熟悉程度：新用户为主

业务场景：教培行业

​

​

2.4 如何抓住核心用户

重点内容

根据目标对象不同，选择合适的营销手段，抓住核心用户：​

1、捆绑式：健身房，美容院：实体店铺为主，基于人性贪便宜爱面子，可以采用会员积分，预充值，买套餐等，捆绑式核心用户

2、低价诱导：大型商超：用户流量为主，对价格敏感，可以提升运营效率，压低成本，例如沃尔玛，开市客，诱导式核心用户（某些商品价格优惠几分钱，门店开到郊区租金低，仓储门店减少了服务员和仓库支出，然后吸引用户很远出过来）

3、高端享受：服务类高端公司：用户服务为主，让付费用户享受优质服务，提高付费用户的优越感，超预期的服务，提高用户的粘度（奈非，亚马逊）

4、网络型：网络价值和用户数量的平方成正比，更容易链式扩散，建立网络关系，用户会自身吸纳更多的用户：建立社群关系，通过社群，粉丝群等，实现口碑传播（腾讯，抖音，小红书，Soul 通讯工具转换成不同的社群）

5、股东型：用户就是公司的股东，用户享受企业发展的红利，核心用户从股东角度考虑公司发展（小米早期发展，汉堡王）：筛选核心优质用户，打造利益命运共同体，给用户主人翁的地位

2.5 场景化分析

场景五要素

5W分析：who where when how what 用户在某个特定的时间和空间里，对应情景下产生的故事就是场景。

分成现实生活中的场景，互联网中的场景。

who：不同类型的用户，核心用户，人口特征，熟悉程度，业务场景等维度

where：国家城市空间的具体位置，产品对应的软件和硬件设备（设备兼容性）

when 时间：固定时间，周期时间，特定时间

how 行为：用户的操作流程和操作动作

what 目的：用户想要什么结果

案例：分析抖音的 5W

who：创作者，浏览者，上班者，农村人，新手玩家，专业用户，直播用户，打赏金主

where+when：睡觉前的床上，上下班的公交车，中午吃饭前后，工作期间摸鱼

how：刷短视频，搜索攻略，抖音商城购物，看直播活动，拍摄短视频

what：打发时间，搜索新闻，查看攻略，买东西，追星，分享自己的生活

场景化分析方法

预判用户行为，发现新的需求：

上下班的公交车上，用户刷视频打发时间，获取新的新闻动态——需求：随时刷，看各种新闻和八卦，网络可能不稳定，需要提前缓存多条视频

睡前打发时间：点赞优质博主，用户互动更多

场景化分析方法的应用

提高预期：个性化推荐用户喜欢的下一个视频，根据用户当前操作推断用户下一步操作（当前截屏，下一步分享），超过预期（用户生日礼物，纪念日礼物等）

​

2.6 需求收集与辨别

1、需求：用户预期和现状的差异，就是用户需求

2、如何获取需求：望闻问切

望：观察法

闻：用户反馈（被动反馈）

3.2 需求分析

重点内容

需求分析的目的

把用户需求（预期，目的，想法，是否是真实的需求，是否符合产品定位和公司业务），转换成产品方案（功能，服务，活动，内容），进一步实现为产品功能（如何实现，有多少种功能，优先级性价比何如）。

需要分析用户需求背后的目的是什么（需求——价值观——本质），人性的本质更持久

例如：福特公司造汽车钱，用户的需求是一匹更快的马（本质是更快的速度），汽车公司使用骑车解决了本质的需求

需求分析的方法

从马斯洛的需求理论分析，或者从人性的弱点进行分析。

需求分析的实际案例

1、傲慢：显示优越感（vip 特权），显示分享，显示点赞数等

2、嫉妒：制造焦虑感，制造不良情绪，追赶他人。常用在游戏设计中，通过排名，拉票等形成嫉妒。

3、愤怒：用户对某些情况很愤怒，需要得到宣泄，所以需要支持拉黑，举报，反馈，不再关注等功能。

4、懒惰：心理厌倦，想休息。产品需要减少思考，减少理解成本。例如：一键复制填写快递地址，推荐算法。

5、贪婪：培养用户贪婪心理，利用用户侥幸心理。主要是拼多多，发优惠券，完成任务发放积分，随机抽奖等。

6、食欲：美食诱惑，吃播，看到其他人吃的好，然后更愿意买东西。

7、色欲：在线直播

需要根据产品的主要客户群体，找到对应人性的弱点，设计对应的产品营销策略。

（例如拼多多，主要群体就是低收入人群，抓住占便宜的心理，然后进行抽奖，优惠券等）

我们还需要多多体验成熟的竞品，如果自己不确定怎么做，抄作业（可以参考同赛道的竞品，也可以跨越赛道参考其他行业的特点，例如把游戏的奖励机制，放在购物产品的奖励机制中，这样可以增加用户粘度）。

3.3 功能优先级划分

学会根据 Kano 模型，评定任务优先级顺序

Kano 模型：对用户需求和优先级排序的工具，分析用户的满意度和产品功能的非线性关系。横轴是功能程度，纵轴是用户满意程度。

操作步骤：

1、做调查问卷：内容是有了这个功能，没有这个功能，用户是否能接受，12345评分，进行投放

2、不同属性的评定：必备属性，期望属性，魅力属性，反向属性，无差异属性，可疑结果几种。

  • 必备属性：必须有这个功能，去掉这个功能不能接受。

  • 期望属性：非常建议有这个功能

  • 魅力属性：很希望有这个属性，去掉这个属性无所谓

  • 反向属性：不建议增加这个属性

  • 无差别属性：是否增加这个属性，无所谓

  • 可疑结果和可疑问卷：前后矛盾等

3、评定功能优先级后，放在 Kano 模型中进行投图：

需要做：必备属性 > 期望属性 > 魅力属性。

反向属性（开屏广告），根据各方利益后（使用者，广告商，利益不同），再决定是否调整。

系数计算：用 Better-Worse 系数量化影响 ——Better 系数（正向满意度提升）Worse 系数（负向满意度下降），优先处理高 Worse（基本型）和高 Better（兴奋型）需求。

案例

需求名称 正向问题答案 反向问题答案 需求类型 Better 系数 Worse 系数 优先级 行动建议
智能手表防水 一般 很不满意 基本型 0.2 -0.8 高 必须达标 IP68
心率监测精度 满意 不满意 期望型 0.6 -0.5 中 提升至行业 TOP3
呼吸训练 很满意 一般 兴奋型 0.9 -0.1 中高 优先开发
冗余通知 不满意 满意 反向型 -0.3 0.4 低 移除功能

3.4 功能价值

衡量功能是否有价值？能够评估功能价值。​

功能价值 = 功能实际价值 / 功能实现成本

价值评估

实际价值：范围价值（用户数 x 单用户价值）+ 频次价值（需求频次 x 每一次的价值） + 时间价值(持续时间 x 单位价值)

需要看产品收费模式，按照用户个数收费，还是按照API调用次数收费，还是按照服务器按年收费等。

案例：

范围：从单一工具，扩展到社群，用户数会增加

频次：从每天看一次天气，扩展到其他信息，打开次数增加

时间：拍视频，浏览短视频，会增加用户的持续时间

数据统计平台中，会显示增加了新功能，对应的增加用户数量的反馈。我们可以进行数据埋点，或者 API 服务器分析等，获取不同入口的用户数量，根据历史数据预测，上线之后小规模试点等。

备注：如果是C端可以采用这个方式，如果是B端可能无法直接获取新功能的反馈情况。

5.2 思维导图的作用和应用场景

思维导图：把想法可视化展示的工具（避免大段的文字）。通过关键词，把不同的主题的逻辑关系，隶属关系，层级关系展示出来。通过不同颜色，图片，突出不同的重点。最终绘制出一个重点突出，逻辑鲜明的效果。

常用软件

  • 本地 APP：Xmind, mindmaster, mindmanager 等

  • 在线网页：processOn https://www.processon.com/diagrams, 其他在线 AI 工具有的也可以生成思维导图

主要作用和特点

1、发散思维：把一个概念向外发散，寻求发散的解决方案

2、聚合思维：把多个观点进行归类，概括，总结，提取相同点

3、形象：将枯燥的文字，使用逻辑图形象的展示出来

4、压缩：使用关键字，把大量信息压缩

5、结构化思维：把文本转换成逻辑化，结构化，层次化，进行归类和处理

6、逻辑思维：对想法进行比较、分析、概括和推理。

应用场景

1、演示内容（嵌入到PPT），用于教学，产品演示，个人简介、上级领导报告（周报）

2、项目管理、制定计划、逻辑思考，个人做笔记，背诵记忆（团队和个人都可以）、创意灵感

6.5 页面交互

交互效果：页面整体交互，某个组件局部的交互。页面的交互分成2种：

1、单页页面内部状态的切换：增加多个页面状态，使用全局事件进行触发，或者某个组件进行触发，触发更换到另一个页面状态。在同一个页面状态内部，会丝滑的切换。类似 PPT 动画效果，点击按钮触发图形的动画效果。

案例：添加动态组件，点击页面的小图片，切换到大型图片预览，点击大图片后，返回小图片预览。选中某个图片后，右侧可以设置外观和交互，某个事件触发什么效果。

2、多个页面之间的切换

案例：跳转跳转到某个页面，或者跳转超链接，点击元素后，跳转到第一页（使用一个对勾图标表示跳转效果）

6.6 动态组件

动态组件-组件内部存在一个状态。可以支持位置，大小，颜色的变化。

实现方法：

1、新增传统组件，转换成动态组件。

2、设置组件状态

3、添加组件交互事件

案例：点击按钮后，打开 modal。Modal 有关闭和执行2个按钮。点击关闭就关闭 Modal 点击执行就跳转页面

总结：就是设置多个图层，点击按钮后，跳转到对应的图层效果（使用添加事件进行跳转）。

6.7 长页面及组件相对固定

滚动效果的实现

1、选择1屏线（页面下方的虚线）

2、向下拖动为长页面

3、添加一些内容和元素（列表内容）

​

固定定位的实现

1、选择组件

2、设置运行时固定位置（移动端悬浮按钮在右下角固定）

3、顶部栏和底部栏，标题固定在顶部，拖动左侧和右侧的位置，设置固定定位的位置
